# Foundations and limits

Use these sources to resolve a relevant question, not as required reading on
every invocation. The skill contains an operational synthesis, not the text of
a paid standard or a conformance assessment.

| Source | Status and contribution |
| --- | --- |
| [ISO 24495-1:2023](https://www.iso.org/standard/78907.html) and the [International Plain Language Federation overview](https://www.iplfederation.org/iso-standard/) | Published international standard. Relevant, findable, understandable, usable information, evaluated with intended readers. Applies across written languages. |
| [Diátaxis](https://diataxis.fr/) | Documentation framework. Distinguish learning, doing, understanding, and lookup; adapt to a page's primary job. |
| [Mayer and Fiorella, principles for reducing extraneous processing](https://doi.org/10.1017/CBO9781139547369.015) and the [Cambridge handbook overview](https://assets.cambridge.org/97811076/10316/excerpt/9781107610316_excerpt.pdf) | Learning research. Coherence, signalling, contiguity, segmenting, and prerequisite concepts inform explanations. Effects depend on learner, material, and modality; do not promise fixed gains. |
| [Butterick, Typography in ten minutes](https://practicaltypography.com/typography-in-ten-minutes.html) | Professional typography guidance. Body text, size, line length, spacing, and font choice. This skill's specific CSS defaults are house preferences. |
| [WCAG 2.2](https://www.w3.org/TR/WCAG22/) | W3C Recommendation. Testable accessibility requirements; use applicable A and AA criteria for an AA target. |
| [Making Content Usable for People with Cognitive and Learning Disabilities](https://www.w3.org/TR/coga-usable/) | W3C Working Group Note, supplementary guidance rather than an additional WCAG conformance level. Clear words, predictable layout, manageable chunks, and understandable controls. |

Useful supporting documentation sources:

- [Google developer documentation style guide](https://developers.google.com/style/highlights): reader-focused wording and structure.
- [Microsoft style and voice](https://learn.microsoft.com/en-us/style-guide/top-10-tips-style-voice): direct, useful, approachable communication.
- [Write the Docs: Docs as Code](https://www.writethedocs.org/guide/docs-as-code/): maintaining documentation with review and verification.
- [Art of README](https://github.com/noffle/art-of-readme): orientation and progressive depth.

Standards and guidance were checked on 2026-10-08. ISO 24495-5 on document
design was still a [working draft](https://www.iso.org/standard/92799.html);
it is not treated as a published requirement here. ASD-STE100's controlled
language rules are not applied as a blanket style policy. If formal conformance
to a named standard is requested, obtain the governing edition and assess it
separately without silently changing the user's claims or obligations.
